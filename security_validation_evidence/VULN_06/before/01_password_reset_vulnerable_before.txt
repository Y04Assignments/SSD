VULN-06: INSECURE PASSWORD RESET - BEFORE STATE EVIDENCE
=========================================================
Type: Historical source code evidence (from project audit and Git commit diff)

=== VULNERABLE CODE (BEFORE commit f70aea2) ===

From About.md, Section 8, Finding 6 (lines 201-211):

1. PRNG VULNERABILITY:
   "Reset code is generated with Math.random(), which is a predictable pseudo-random generator."
   
   Vulnerable code (BEFORE):
     // Math.random() is NOT cryptographically secure
     const resetCode = Math.floor(100000 + Math.random() * 900000).toString();
   
   Problem: Math.random() is seeded predictably in V8. An attacker who knows the approximate
   request time and has access to JS timing information can predict the output range.

2. PLAINTEXT TOKEN STORAGE:
   "The code is saved unhashed in User.passwordResetToken."
   
   Vulnerable code (BEFORE):
     user.passwordResetToken = resetCode;   // Plaintext 6-digit code in database!
   
   Problem: If database is compromised, reset codes are directly readable.

3. NO RATE LIMITING:
   "Neither forgot-password nor reset-password enforces rate limiting or account lockout."
   
   Vulnerable code (BEFORE):
     // NO attempt counter
     // NO lockout mechanism
     // NO rate limiting
     if (resetCode !== user.passwordResetToken) {
       return res.status(400).json({ message: 'Invalid or expired reset code' });
     }
   
   Problem: Attacker could send unlimited requests to /api/users/reset-password
   trying all 900,000 possible 6-digit codes within the 10-minute window.

4. TIMING ATTACK VULNERABILITY:
   Vulnerable code (BEFORE):
     if (resetCode !== user.passwordResetToken) { ... }  // Non-constant-time comparison!
   
   Problem: String comparison '!==' is not timing-safe. Side-channel timing 
   could leak information about partial code matches.

=== ATTACK PATH (HISTORICAL - Math.random brute force) ===

1. Attacker requests password reset for target email
2. Server generates 6-digit code via Math.random() (900,000 possibilities)
3. Attacker sends automated requests: 000000, 000001, 000002, ...
4. With no rate limiting, attacker exhausts all possibilities in < 1 minute
5. Code matched → attacker resets victim's password
6. Full account takeover achieved

  - passwordResetAttempts: Number  // Not present
  - passwordResetLockUntil: Date   // Not present
